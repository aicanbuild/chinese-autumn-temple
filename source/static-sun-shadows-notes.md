# Reusing static temple sun shadows

The 4096-pixel desktop sun shadow map previously redrew fixed architectural geometry whenever moving foliage/leaves needed a new shadow. `dist/static-sun-shadows.js` caches an explicit set of ordinary static mesh casters, including the hall, bridge, roof and sculptural furnishings. Every update restores their packed color **and depth** before drawing dynamic casters. The interior spotlight still draws its complete caster list independently.

A WebGL2 framebuffer blit copies both attachments in one operation. `renderer.resetState()` restores the documented Three.js interoperability boundary before normal rendering resumes. Framebuffer bindings are queried only when storage is allocated, resized, disposed or restored after context loss; no private renderer properties are used. An earlier implementation using two `copyTextureToTexture` calls passed all pixel comparisons but was rejected: its synchronous GL state queries produced a 389 ms CPU median in the timing fixture. The accepted path has no per-update GL state query.

Eligibility excludes instanced, batched, skinned, morphed and custom-shadow meshes. Shadow visibility, ancestor visibility, transforms, geometry/buffer identities and versions, draw ranges, groups, layers, material/alpha/displacement texture state, clipping, light projection and map dimensions invalidate the cache. The app's moving bell, broom, incense, leaves, fish and wind-deformed vegetation remain outside the selected roots. LOD geometry changes rebuild the cache. The feature falls back to full rendering when disabled or when the shadow type is unsupported. Renderer target/cube face/mip and caster flags are restored after drawing failures; disposal releases the additional target and restores the original shadow renderer.

The extra persistent allocation is approximately 128 MiB at 4096², or 32 MiB at 2048², for RGBA8 color plus the depth attachment. It exchanges GPU memory and a framebuffer copy for fewer geometry draws. A rebuild draws the selected geometry once again; rapid changes to selected geometry can remove the benefit. Geometry and materials are unchanged, and Blender files require no edit.

## Validation

- Synthetic real-WebGL fixture: six states (moving caster, moved/hidden static caster, light movement), color and packed sun shadows byte-identical.
- Actual temple fixture: six cameras at two wind times; all twelve final colors, sun shadow maps and interior spotlight maps byte-identical. Each reused update removes 2,789,264 submitted triangles and 49 draws. Fixture cache: 49 meshes, one build, thirteen reuses.
- Alternating actual-model timing fixture: 36 GPU samples per mode. Full shadow median 10.183 ms, cached 7.56275 ms (about 25.7% lower); means 25.2456 and 9.7100 ms. CPU medians after discarding the first three samples per mode: 0.9 and 1.0 ms, with 33 samples each. There were no disjoint/discarded queries or warning/error logs. Large timing outliers and query overhead mean these figures are local evidence, not a whole-scene FPS guarantee.
- 216 tests passed, plus the two added tests for resized/disposed storage, context restoration and interleaved-buffer changes (218 distinct tests total). Tests also cover dynamic/static separation, other-light completeness, invalidation and failure cleanup.

Local evidence: `evidence/static-sun-shadows-browser.json`, `temple-shadow-cache-browser.json`, `temple-shadow-cache-timing.json` and fixture screenshot. `shadow-copy-api-rejected-timing.json` retains the rejected approach's measurements. The fixture uses actual assets but omits some recent decorative replacements and full-app postprocessing; integrated preview QA covers their presence and operation. Overall commercial AAA fidelity and performance remain incomplete.

Integrated runtime `3ffb5d5d2e36`: 66 selected meshes, cache rebuilds across LOD/camera transitions followed by 1,131 reuses after the interaction check. Hall entry, incense ignition, return, broom pickup, 31 swept leaves and broom return passed with no browser warning/error logs. Public diagnostics recorded 131.9 ms overview and 82.3 ms hall frame averages during this check, so whole-scene performance plainly remains below the intended target. Those are uncontrolled integrated observations, not an A/B benchmark. Evidence: `evidence/static-sun-shadows-main.json` and `static-sun-shadows-main-hall.png`.
