# 庭院枝干树皮方向

近景检查发现，15 棵庭院树的融合主干在体素重构后，原先统一按相对树心的 atan2 和世界高度分配纹理坐标。对横向枝条，这会把树皮裂纹拉成横向环带；继续增加纹理分辨率不能修正这个方向错误。

`tree_bark_uv.py` 使用原树木构建器的确定性中心路径，在融合表面上按距离与法线方向选择对应枝干，以弧长和运输局部坐标架铺设树皮。枝条接缝尽量放在下侧，并在单个面内解开角度跨界。保留原贴图、法线强度、粗糙度与树形；原本沿细枝方向铺设的 UV 和六棵松树不变。该方法仍有分枝 UV 接缝和梢端周向压缩，不是无接缝扫描模型。

`refine_tree_bark.py` 备份并更新 `庭院曲枝树木.blend` 与 `听秋寺院.blend`，重开后核验 36 / 7949 个对象的几何、变换、材质不变，其余对象的 UV 也不变；只有 15 个融合主干部件改 UV。中心路径随机数回放与现有 2835 个叶簇锚点逐项吻合。原树木构建器也已接入该映射，之后重建不会恢复旧错误。远景树木由更新后的原生工程重新派生。

## 验证

- 185 项原有检查通过，包含真实 GLB 的 36 个网格、法线、UV、共享纹理、原种植坐标和近远景切换。
- `verify_tree_bark.py` 检查水平、竖直、倾斜三个方向的弧长投影；再对新旧原生模型完全相同的 152122 个侧枝三角面计算纹理映射雅可比的奇异值比，按实际表面积加权。中位数由 5.89 降至 3.84，95 分位由 71.60 降至 8.49，超过 20 倍各向异性拉伸的面积占比由 17.56% 降至 0.127%。这只衡量侧枝 UV 拉伸，不代表整模型美术质量分数。
- `tree-bark-fixture.html` 使用同一树、材质、光线和镜头切换原/新模型，横枝环状拉纹已明显消除。对照页刻意不画树冠，地面是简化平面，不用它判断真实地形的根部接触。证据 `evidence/tree-bark-before.png`、`tree-bark-after.png`、`tree-bark-uv-audit.json`、`tree-bark-native.json`。
- 网页近景资产约 1.81 MiB（原 1.64 MiB），远景约 640 KiB（原 570 KiB）；因 UV 岛边界拆分顶点，下载体积有所增加，原三角面数量与材质批次不增加。

商业 3A 整体画面与性能目标仍未完成。

## 枝杈双映射过渡

`bark_junctions.py` 在 15 棵融合主干的主干/侧枝交界处增加第二套顺枝投影以及约 5.5cm 的平滑权重。原有第一套 UV 与所有顶点、拓扑、变换保持不变。根部延续原映射。原生存储为 `BarkBlendUV` 与 CORNER `_BARK_BLEND`，后者随近景和远景 GLB 一起导出。

`dist/bark-junctions.js` 复用既有树皮图片，在混合区域衔接颜色、粗糙度；两套法线先分别变换到视空间再混合，避免直接混合不同切线空间的方向。导数在一致控制流内求值。15 根主干共用一个新材质，细枝和云松保留普通材质，绘制数量与贴图载荷不增加；主干着色器多三次纹理采样，不宣称帧率提高。

`refine_bark_junctions.py` 保留可恢复备份并更新两份原生文件；`verify_bark_junctions.py` 只读对照备份和当前文件，验证全部几何、原 UV、变换与非目标材质，核对新属性有限、权重 0–1、第二 UV 与属性一致。36 / 9772 对象核验通过。中间第一次尝试在新增属性后使用了失效的 Blender UV 引用，被保存前断言拦下；修正为重新获取引用。另一次报告输出遇到 numpy 整数序列化失败，模型已保存且重开验证通过；之后独立只读核验生成最终 `evidence/bark-junction-native.json`。

近景对照 `source/bark-junction-fixture.html` 直接加载修改前 GLB 与新 GLB，截图 `evidence/bark-fork-before.png` / `bark-fork-after.png`。完整场景检查通过 `source/build_bark_audit.py` 生成。23 项树木、远近切换、阴影、场景变换、分块与构建测试通过。此项修复枝杈贴图接缝，整体商业 3A 目标仍未完成。

## 主枝近端弧度

`branch_cambers.py` 在原有主枝的前六个路径节点范围内施加缓和弯曲与少量枝领膨胀，权重连续地衔接主干；在第一个细枝接点之前归零。15 棵树采用固定的不同相位，不改变种植或树冠随机序列。原 UV、双映射权重随曲面一起保留。初版弧度过于集中，只输出本地临时预览；采纳版改为更宽的正弦平方曲线和较小幅度。

`refine_branch_cambers.py` 先备份再更新两份原生模型，保护所有网格拓扑、UV、混合属性、材质与变换；非目标对象的顶点也保持不变。36 / 9772 对象核验通过。实际改变 38442 个顶点，最大位移约 7.51cm；逐三角形法向与原值点积最小 0.662，面积比最小 0.599，所有实体体积为正。细枝连接处检测到的最大位移为 0，1.35m 以下根部坐标不变。保存后重开再次核对两份工程的目标坐标完全一致。报告为 `evidence/tree-cambers-native.json`。

近景 474564 / 远景 99783 三角形均保持原数；每个 GLB 中的 21 个细枝与云松压缩网格二进制逐字不变。7 项树木与构建检查通过。`verify_bark_junctions.py` 在只读对照时可计入已审核的枝形修订，仍验证原 UV 与树皮过渡属性。

对照页 `source/tree-cambers-fixture.html` 加载修改前资产和正式导出。截图 `evidence/tree-cambers-before.png` / `tree-cambers-after.png`，正式庭院截图 `evidence/tree-cambers-main.png`。浏览器无警告或错误。该项只改主枝近端形态，没有增加交互、网格数量或着色器采样；整体商业 3A 目标仍未完成。
